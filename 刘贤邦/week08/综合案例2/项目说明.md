# 项目说明 · 深度研究助手

> `README.md` 是题目要求，本文件是实现说明（使用方法 + 架构设计）。

## 一、这是什么

输入一个研究主题，自动完成 **规划（拆子问题）→ 多轮检索 → 阅读抽取 → 判断补检 → 综合报告**，产出一份带来源引用、可追溯的中文研究报告。

对应题目要求的四项输出：

| 题目要求 | 落点 |
|---|---|
| ① 结构化研究报告（摘要/分节正文/关键结论/遗留问题） | `report.md` 正文 |
| ② 来源列表（结论关联 URL，可追溯） | `report.md` 文末「来源列表」，正文 `[n]` 角标与其严格对账 |
| ③ 研究过程记录（检索词/读了哪些页面/迭代轮数） | `process.json`（前端可折叠查看） |
| ④ 置信度说明（可靠程度/信息截止/模型推断标注） | `report.md`「置信度说明」章节 + 正文无来源句标注（模型推断） |

## 二、怎么跑

```bash
# 1. 安装依赖（Python 3.10+）
pip install fastapi uvicorn openai httpx python-dotenv

# 2. 确认 .env 已配置（key 不入库，见 .env 内注释）

# 3. 启动
python -m uvicorn main:app --host 127.0.0.1 --port 8000
# 或：python main.py
```

浏览器打开 <http://127.0.0.1:8000>，输入主题 → 「开始研究」，页面实时显示进度（当前轮次/已读来源/检索次数），完成后渲染报告，可下载 `report.md`、展开研究过程记录。

一次研究约 2~5 分钟。产物同时落盘到 `output/<时间戳>-<主题>/`：

```
output/20261004-095759-.../
├── report.md      # 研究报告（含来源列表、置信度说明）
└── process.json   # 研究过程记录
```

## 三、架构设计（混合式）

脚本控制循环骨架（可控、过程可记录），LLM 负责各环节的智能部分：

```
main.py（单文件）
├── 配置        .env → 模型/密钥/轮数/检索条数/原文抓取开关
├── LLM 封装    llm()/llm_json()：重试 LLM_RETRIES 次；DeepSeek 只支持
│               json_object（无 json_schema），解析做正则兜底
├── 工具        bocha_search()      博查网页搜索（summary 摘要）
│               fetch_page_text()  原文抓取增强（失败静默降级回摘要）
├── 流水线      stage_plan()        规划：拆 3~5 个子问题 + 检索词
│               stage_extract()    阅读抽取：信息点 + 来源归属
│               stage_judge_gaps() 缺口判断：对照子问题，够了就停
│               stage_write()      综合：生成带 [n] 引用的报告
│               stage_rewrite()    引用校验不过时打回重写一次
├── 校验        validate_citations() 正文 [n] ↔ 来源编号对账
│               finalize_sources()  按实际引用裁剪来源并连续重编号
└── Web         FastAPI：POST /api/research 启动任务（后台线程）
                GET  /api/research/{id} 轮询进度/报告/过程
                GET  /  static/index.html（原生 JS + CDN marked.js）
```

**循环骨架**：第 1 轮用规划出的检索词 → 检索（URL 全局去重）→ 按子问题抽取要点 → LLM 对照子问题判断缺口：信息足够则提前结束，否则生成补检词进入下一轮；**硬上限 `RESEARCH_MAX_ROUNDS`（默认 3）轮**。

**引用可信度的三道保障**：

1. 抽取阶段只允许从给定 URL 中选来源，不许编造；
2. 写作阶段强制正文结论带 `[n]` 角标，无来源判断必须标（模型推断）；
3. 成稿后程序校验角标与来源对账，不合规打回重写一次；来源列表由程序按实际引用裁剪重编号，杜绝"列表对不上正文"。

## 四、配置项（`.env`）

| 变量 | 说明 | 默认 |
|---|---|---|
| `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` | DeepSeek（OpenAI 兼容）密钥与地址 | — |
| `MODEL_NAME` | 全环节统一模型 | `deepseek-flash` |
| `BOCHA_API_KEY` / `BOCHA_SEARCH_COUNT` | 博查搜索密钥 / 每次检索条数 | — / `10` |
| `RESEARCH_MAX_ROUNDS` | 检索迭代硬上限 | `3` |
| `LLM_RETRIES` | LLM 调用失败重试次数 | `3` |
| `FETCH_ORIGINAL` | 摘要太薄时是否抓原文增强（失败自动降级） | `true` |

## 五、已知局限

- 博查摘要偶尔较薄，原文抓取是正则粗提正文，对强反爬站点会降级回摘要；
- 引用校验保证「编号对账」，但"结论是否真的被来源支持"依赖 LLM 抽取阶段的约束，未做人工核查；
- 单任务串行（后台线程），适合作业/单人使用，未做并发队列。
